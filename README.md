# Fridge Ops

Внутренний сервис, который каждый час отвечает на вопрос **«что сейчас нужно сделать?»**:
что переместить, откуда, куда, сколько, почему и насколько срочно.
Цель: меньше пустых холодильников и списаний, больше продаж, никакой ручной аналитики.

> **KitShop используется только для чтения.** В коде нет ни одного метода записи.
> Сейчас приложение работает на встроенном симуляторе (`DATA_SOURCE=mock`) и не обращается к KitShop.

## Три клиента — один бэкенд

```
Fridge Ops backend (Next.js API + PostgreSQL)
├── Desktop web      — Command Center, Analytics, Настройки (менеджер / админ)
├── Mobile web / PWA — /m, интерфейс сотрудника
└── Android app      — Capacitor-оболочка вокруг /m (kz.greencity.fridgeops)
```

Пользователи, холодильники, товары, остатки, маршруты, XP, OPS POINTS, награды, история и прогнозы хранятся **только на сервере**.
Телефон держит лишь временный прогресс начатой задачи до отправки.

## Запуск

**Проще всего (Windows):** дважды нажмите `start.bat` в папке `fridge-ops`. При первом запуске он сам поставит зависимости и откроет браузер.

Или вручную из папки `fridge-ops`:

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. В режиме разработки при первом запуске создаются демо-аккаунты
(**только локально, в проде их нет** — там первый админ берётся из `ADMIN_LOGIN` / `ADMIN_PIN`):

| Логин | PIN | Роль |
|---|---|---|
| `anna` | 3333 | сотрудник → сразу `/m` |
| `manager` | 2222 | менеджер → Command Center |
| `admin` | 1111 | администратор → всё + Настройки |

Проверки (то же самое запускает CI на каждый push):

```bash
npm run typecheck
npm test
npm run build
```

### С телефона в локальной сети (для разработки)

Для работы сотрудников нужен прод-сервер (docs/DEPLOYMENT.md) — тогда не нужны ни одна Wi-Fi сеть, ни `start.bat`.
Для проверки на телефоне во время разработки:

1. Телефон и компьютер в одной Wi-Fi сети.
2. Запустите `start.bat` (он слушает сеть: `-H 0.0.0.0`). В окне будет строка `Network: http://192.168.x.x:3000`.
3. Откройте этот адрес на телефоне. Телефон сразу попадает в интерфейс сотрудника `/m`.
4. «Поделиться → На экран Домой» (iPhone) или «Установить приложение» (Android) — Fridge Ops откроется как отдельное приложение.
   Service worker (работа при плохой связи) включается в production-режиме: `npm run build && npm run start -- -H 0.0.0.0`.

Если Windows спросит про брандмауэр — разрешите доступ для частной сети.

## Что внутри

**Телефон = выполнение** (`/m`, mobile first):

| Экран | Что показывает |
|---|---|
| 🏠 Сегодня | 🟢/🟡/🔴 по сети, одна главная задача крупно, следующие задачи, XP и точность за день |
| ✅ Задачи | маршруты: `САТТИ 5 → САТТИ 1 → САТТИ 13`, конкретные блюда и количество |
| Задача | «Возьми» (блюдо, категория, SKU, ×N) → «Положи в» по остановкам → «Почему» (+ «Подробнее») → **НАЧАТЬ** |
| Чек-лист | на весь экран: «ЗАБЕРИ ИЗ» → «НЕСИ В» по каждой точке, кнопка «Есть только N», прогресс хранится на телефоне |
| 🧊 Холодильники | статус и **реальные названия блюд** с количеством по категориям |
| 🏆 Рейтинг | XP, уровень, OPS POINTS (сегодня / неделя / всего), награды 1000/3000/5000, команда, достижения |

**Компьютер = анализ и управление:** Command Center `/`, Analytics, History, Heatmap, симулятор (DEV PANEL), **Настройки** `/admin`
(display_name / short_name холодильников, локация, приоритет, зона близости, график, время в пути, выдача наград).

Как это работает:
- Движок решает на уровне **блюда**: `нужно(точка, блюдо) = спрос + запас − остаток`. Если в точке уже много этого блюда, туда его не повезут.
  Среди нужных блюд выбираются те, что лучше продаются именно там (affinity 0–100 по истории).
- Переносы из одного холодильника собираются в **один маршрут** (до 3 остановок, порядок — ближайшая следующая точка, маршрут ≤ 35 мин).
- XP начисляется за работу, **OPS POINTS — только за подтверждённый результат** (через 2 часа проверяется, продались ли блюда). Награды не выдаются автоматически — администратор отмечает выдачу.
- Нет связи — отметки сохраняются на телефоне, действие «Готово» отправится само, когда связь вернётся. KitShop по-прежнему только читается.

Все параметры движка — в [src/lib/config/engine.ts](src/lib/config/engine.ts).

## Структура

```
src/lib/engine/      history → forecast → risk → profile → recommend → scoring → feedback (чистые функции)
src/lib/simulator/   15 архетипов, 180 дней истории, живой день по 15 минут
src/lib/server/      runtime (миссии, XP), пользователи и сессии, уведомления, view-модели
src/lib/store/       хранилище: PostgreSQL (прод) или файл (разработка)
src/services/kitshop READ-ONLY клиент, адаптер, диагностика
src/lib/sync/        инкрементальная синхронизация (Phase 2)
prisma/schema.prisma целевая нормализованная схема (для роста)
android/             Capacitor Android-проект (generated + иконки/сплэш/подпись)
deploy/              Caddyfile, пример .env.production, бэкап
tests/               движок, вход, хранилище, безопасность
```

## Этапы

- **Готово:** симулятор, desktop, мобильный интерфейс, маршруты по блюдам, XP / OPS POINTS / награды, вход по PIN и роли,
  PostgreSQL, Docker, CI, Android-приложение.
- **Phase 2:** получить документацию KitShop → подтвердить методы в `READ_ENDPOINTS` → PostgreSQL + Prisma → sync.
- **Phase 3:** `DATA_SOURCE=kitshop`, реальные данные, калибровка параметров по фактической точности.
