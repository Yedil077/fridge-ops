# Apps Холодосов — безопасность

## Главные правила

1. **KitShop: чтение — отдельно, запись — за шлюзом.** Read-клиент (`src/services/kitshop/kitshopClient.ts`) содержит только `get*`-методы
   из белого списка документированных методов (официальная API v1.3: все методы POST, подпись MD5 в теле). Запись
   (загрузка/снятие/списание через `MakeFillUp`, создание товара `AddProduct`) — только в `writer.ts` и только когда
   `KITSHOP_ENABLED=true`, `KITSHOP_WRITE_ENABLED=true`, `KITSHOP_WRITE_DRY_RUN=false` **и** точка в `KITSHOP_WRITE_SHOPS`.
   По умолчанию запись выключена; иначе — тренировочный KiT Shop (mock) или dry-run (только журнал).
   Удаление товаров, удаление из товарной базы и команды терминалу/замкам (`AddCommand`) в коде отсутствуют.
   Идемпотентность — `operation_uuid`; потерянный ответ → UNKNOWN и проверка чтением, без автоповтора. Каждая запись — в audit log.
   Подробно: `docs/KITSHOP_WRITE_API_AUDIT.md`. Проверяется тестами `tests/security.test.ts`, `tests/kitshopOps.test.ts` в CI.
2. **Секреты только на сервере.** Логин/пароль KitShop, пароль базы, `AUTH_SECRET` живут в `.env.production` на сервере.
   Их нет во фронтенде, в APK, в localStorage и в git (`.gitignore` + тест).
3. **Правильный путь данных:** `Android/браузер → Apps Холодосов backend → KitShop (READ ONLY)`. Телефон никогда не обращается к KitShop.

## Вход и сессии

- Сотрудник: логин + PIN (4–8 цифр). PIN хранится как scrypt-хеш с солью, в открытом виде нигде не сохраняется.
- 5 неверных PIN подряд → логин блокируется на 5 минут.
- Сессия: случайный 256-битный токен в httpOnly cookie (`Secure` в проде, `SameSite=Lax`), в базе только его sha256.
  Срок 180 дней, продлевается при использовании — сотрудник не вводит PIN каждый раз.
- Отзыв: администратор отзывает отдельное устройство или все сессии пользователя; смена PIN и отключение пользователя выходят со всех устройств.
- Выход на устройстве отзывает сессию на сервере и очищает кеш service worker (личные данные не остаются на общем телефоне).

## Роли

| Роль | Доступ |
|---|---|
| EMPLOYEE | `/m`: задачи, маршруты, холодильники, свои очки и награды |
| MANAGER | + Command Center, профиль холодильника, запуск анализа |
| ADMIN | + Analytics/History/Heatmap, настройки холодильников, пользователи, сессии, награды, DEV-панель симулятора |

Роли проверяются в каждом API-обработчике (`requireUser(role)`). Подписанная cookie роли в middleware используется только для
маршрутизации (сотрудник → `/m`) и не даёт доступа сама по себе.

## Прочее

- Проверка `Origin` для изменяющих запросов (защита от CSRF в дополнение к `SameSite`).
- Заголовки: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, HSTS (Caddy).
- Контейнер работает от непривилегированного пользователя.
- DEV-панель (изменение симулятора) доступна только администратору и только в режиме `mock`.

## Найдено и исправлено в этой версии

| Было | Стало |
|---|---|
| Личность = любое введённое имя, общий код доступа | учётные записи + PIN (хеш) |
| Администратор по списку имён `ADMIN_NAMES` (подделывается) | роль в базе |
| Сессию нельзя отозвать | сессии в базе, отзыв по устройству |
| Нет ограничения попыток входа | блокировка после 5 ошибок |
| DEV-панель доступна всем | только ADMIN |
| Service worker хранил личные ответы после выхода | очистка кеша при выходе |
| Состояние в файле на диске | PostgreSQL в проде; файл только для разработки |

## Остаточные риски

- `start.bat` для разработки слушает локальную сеть (`-H 0.0.0.0`) — не использовать его как прод-сервер.
- Лимит попыток входа хранится в памяти процесса и сбрасывается при перезапуске.
- Доступ к серверу (SSH, панель провайдера) защищайте ключами и 2FA — это вне приложения.
